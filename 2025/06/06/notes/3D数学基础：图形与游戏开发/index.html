《3D数学基础：图形与游戏开发》全书内容提炼总结

notes 3D数学基础 图形学 2025/06/06

前言

《3D数学基础：图形与游戏开发》（3D Math Primer for Graphics and Game Development，Fletcher Dunn / Ian Parberry 著）是图形和游戏开发的经典入门书。它不追求数学证明，而是讲清楚每个概念的几何意义，并给出可直接使用的C++实现。

全书主线：坐标系 → 向量 → 矩阵与变换 → 方位（矩阵、欧拉角、四元数）→ C++实现 → 几何图元与几何检测 → 三角网格 → 图形管道 → 可见性检测。

本文约定：

  • 使用左手坐标系：+x向右，+y向上，+z向前（指向屏幕里）。
  • 使用行向量，向量左乘矩阵：v' = vM，多个变换从左往右读：v' = vABC 表示先A再B后C。
  • 角度正方向由左手法则确定。
  • 博客不渲染数学公式，公式写在代码块中：· 表示点乘，× 表示叉乘，|v| 表示模，ᵀ 表示转置。

一、笛卡尔坐标系

1. 1D数学

  • 自然数、整数是离散的，实数是连续的。计算机只能存有限精度的数，所以计算机中的“实数”其实是近似。
  • 图形学第一定律：如果它看上去是对的，它就是对的。 图形和游戏追求的是视觉上正确，大量计算都可以近似。

2. 2D笛卡尔坐标系

  • 由原点和两条互相垂直、过原点的坐标轴组成。原点决定位置，坐标轴决定方向和刻度。
  • 点用坐标(x, y)表示，即沿x轴、y轴的有符号距离。
  • 两轴的朝向可以任意选，通过旋转和翻转共有8种方案，但它们本质等价：任意一种都能旋转（或翻转）成另一种。常用：+x向右，+y向上。

3. 3D笛卡尔坐标系

  • 增加z轴表示深度，三轴两两垂直。点用(x, y, z)表示。
  • 3D坐标系分两种，不能通过旋转互相转换：
    • 左手坐标系：左手拇指指向+x，食指指向+y，中指指向+z。标准形式：+x右、+y上、+z向前（屏幕里）。
    • 右手坐标系：同样的手势换右手。标准形式下+z向屏幕外。
  • 同一种手系通过旋转有24种形式，共48种。
  • 两者只差z轴方向，换手系时把z取反即可。
  • 旋转正方向（左手法则）：左手拇指指向旋转轴正方向，四指弯曲的方向就是正方向。从轴的正端往原点看，左手系中正旋转是顺时针，右手系中是逆时针。
  • 本书使用左手系；DirectX习惯左手系，OpenGL习惯右手系。数学本身不受影响，影响的只是如何解释数字。

请记住：

  • 计算机中的连续量都是近似，“看起来对就是对的”。
  • 3D坐标系分左手系和右手系，两者不能通过旋转互换，只差z轴方向。
  • 本书使用左手系：+x右、+y上、+z前，正旋转从轴正端看是顺时针。

二、多坐标系

1. 为什么需要多个坐标系

一个坐标系理论上能描述所有点，但很多问题换一个坐标系会简单得多。例如“NPC在我左边吗？”在角色自己的坐标系中只需看x的正负。计算多个点的关系时，必须先把它们转换到同一个坐标系。

2. 常用坐标系

  • 世界坐标系：全局坐标系，描述其他坐标系的参照。它能描述其他坐标系，反过来不行。“这个物体在哪？”“从A到B怎么走？”这类问题在世界坐标系中回答。
  • 物体坐标系（模型坐标系）：每个物体独有，随物体移动和旋转。“前后左右”就是物体坐标系中的概念。
  • 摄像机坐标系：观察者的物体坐标系。本书中+x向右、+y向上、+z为摄像机朝向。用于判断“物体是否在视野内”“谁挡住了谁”。注意它与屏幕坐标系（2D）不同。
  • 惯性坐标系：原点与物体坐标系原点重合，轴与世界坐标系平行。它是物体坐标系和世界坐标系之间的“半途”：
    • 物体坐标系 → 惯性坐标系：只需旋转。
    • 惯性坐标系 → 世界坐标系：只需平移。

3. 嵌套式坐标系

物体可以由多个部件组成，每个部件有自己的坐标系，相对于父部件定义，形成树状层次。例如人体：躯干 → 上臂 → 前臂 → 手。父坐标系移动或旋转，子坐标系跟着变化。世界坐标系是这棵树的根。

4. 描述坐标系与坐标系转换

  • 描述一个坐标系，就是给出它的原点位置和三个轴的方向（基向量），都用父坐标系的坐标表示。
  • 坐标系转换：已知点在某个坐标系中的坐标，求它在另一个坐标系中的坐标。
  • 理解变换有两种视角：变换物体（物体动、坐标系不动）和变换坐标系（物体不动、坐标系动）。二者等价，方向相反：把物体顺时针转20°，等于把坐标系逆时针转20°。

请记住：

  • 选对坐标系能让问题变简单；计算前先统一坐标系。
  • 世界、物体、摄像机、惯性坐标系是最常用的四种；惯性坐标系把物体→世界拆成“先旋转、再平移”。
  • 变换物体与变换坐标系是同一件事的两种视角，方向相反。

三、向量

1. 数学定义

  • 向量就是一个数字列表，维度是数字的个数。标量是普通的数。
  • 写法：行向量[1 2 3]或列向量（竖着写）。本书默认用行向量。
  • 分量用下标表示：v = [vx vy vz]。

2. 几何定义

  • 向量是有大小和方向的有向线段（箭头），没有位置。
  • 箭头可以放在任何位置，只要大小和方向相同，就是同一个向量。
  • 几何意义是位移：[1 -3 4]表示向右1、向下3、向前4，三步顺序无关。
  • 速度、加速度、力都是向量。

3. 向量与点

  • 点表示位置，向量表示位移。
  • 任意点都可以表示为从原点出发的向量：点(x, y)对应向量[x y]。
  • 位置只有相对意义，描述点的坐标本身就是“相对原点的位移”。所以点和向量在数学上写法相同，概念上不同。

请记住：

  • 向量有大小和方向，没有位置，几何上表示位移。
  • 点是位置，可以看作从原点出发的位移向量。

四、向量运算

线性代数把向量当成数组来运算，几何把它们当成箭头。每种运算都要同时理解代数公式和几何意义。

1. 零向量和负向量

  • 零向量：[0 0 0]，唯一没有方向的向量，表示“没有位移”。
  • 负向量：-v = [-vx -vy -vz]，大小相同、方向相反。v + (-v) = 0。

2. 向量大小（模）

几何上就是勾股定理：分量是直角边，向量是斜边。

3. 标量与向量的乘法

  • 几何意义：长度缩放|k|倍，k < 0时方向反转。
  • 标量不能除以向量，向量也不能加标量。

4. 标准化向量

  • 得到大小为1的单位向量（又叫法线），用于只关心方向的场合。
  • 零向量不能标准化。

5. 向量加法和减法

  • 几何：三角形法则——把b的尾接到a的头，从a尾指向b头的向量就是a + b。
  • a - b是从b的头指向a的头的向量。
  • **从点a到点b的向量是b - a**。

8. 叉乘

仅用于3D向量，结果是向量：

  • a × b垂直于a和b。
  • 长度等于以a、b为两边的平行四边形面积。
  • 方向：左手系中，如果a和b首尾相接后呈顺时针，a × b指向你；逆时针则背离你（右手系相反）。
  • a × b = 0表示a、b平行（或有零向量）。
  • 不满足交换律：a × b = -(b × a)；也不满足结合律。
  • 主要用途：求平面、三角形、多边形的法向量。

9. 线性代数公式

请记住：

  • 从点a到点b的向量是b - a，两点距离是它的模。
  • 点乘得标量，a·b = |a||b|cosθ，用于判断夹角、求投影。
  • 叉乘得垂直向量，长度为平行四边形面积，用于求法线；它不满足交换律。

六、矩阵

1. 数学定义

  • 矩阵是按行和列排列的数字块，可以看作二维数组。r×c矩阵有r行c列。
  • 元素mij表示第i行第j列，下标从1开始。
  • 方阵：行数等于列数。行列号相同的元素是对角线元素。
  • 对角矩阵：非对角线元素全为0。
  • 单位矩阵I：对角线为1、其余为0的方阵。任何矩阵乘以I都不变，地位相当于标量中的1。
  • 向量是特殊的矩阵：行向量是1×n矩阵，列向量是n×1矩阵。

2. 转置

把行变成列：(Mᵀ)ij = Mji。

行向量转置就是列向量。

3. 标量与矩阵相乘

每个元素都乘以该标量：(kM)ij = k·mij。

4. 矩阵乘法

r×n矩阵A乘以n×c矩阵B，得到r×c矩阵：

  • A的列数必须等于B的行数，否则无定义。
  • 不满足交换律：一般AB ≠ BA。
  • 满足结合律：(AB)C = A(BC)；满足数乘结合：(kA)B = k(AB) = A(kB)。
  • MI = IM = M。

5. 向量与矩阵相乘

  • 行向量只能左乘矩阵（vM），列向量只能被矩阵左乘（Mv）。
  • 两种写法结果的元素相同，只差一次转置，对应的矩阵互为转置。
  • 行向量的优点：多个变换从左往右读vABC就是先A再B后C。列向量要写成CBAv，从右往左读。
  • DirectX用行向量，OpenGL用列向量。 看别人的公式时要先确认约定，必要时转置矩阵。

6. 矩阵的几何解释

  • 方阵可以描述线性变换：旋转、缩放、投影、镜像、切变。线性变换保持直线和原点不变，网格线不会弯曲。
  • 关键：矩阵的每一行就是变换后的基向量。
  • 原来的x轴[1 0 0]乘M后就是第一行p，y轴变成q，z轴变成r。
  • 所以只要知道变换后基向量去了哪里，就能直接写出矩阵；反过来，看矩阵每一行就能“看出”它做了什么（画出变换后的坐标轴）。

请记住：

  • 矩阵乘法要求左矩阵列数等于右矩阵行数；不满足交换律，满足结合律；(AB)ᵀ = BᵀAᵀ。
  • 行向量写vM，变换从左往右读；列向量写Mv，两者矩阵互为转置。
  • 矩阵每一行是变换后的基向量，这是理解所有变换矩阵的钥匙。

8. 变换分类

  • 线性变换：满足F(a+b) = F(a) + F(b)、F(ka) = kF(a)。原点不动，可用3×3矩阵表示。

  • 正交变换：轴保持互相垂直且长度不变。平移、旋转、镜像。

八、矩阵的更多知识

1. 行列式

只有方阵有行列式，记作|M|或det M。

3×3行列式也等于三行的混合积：(r1 × r2) · r3。

余子式与代数余子式（用于任意n×n）：

  • 余子式M{ij}：删掉第i行第j列后剩下的矩阵。
  • 代数余子式：cij = (-1)^(i+j) · |M{ij}|。
  • 按任意一行（或列）展开：|M| = Σj mij·cij。
  • 计算量随阶数指数增长；还有“主元选择”等更快的方法。

性质：

几何意义： 2D中是以基向量为边的平行四边形的有符号面积，3D中是平行六面体的有符号体积。也就是变换带来的面积/体积缩放比例。

  • |M| = 0：矩阵包含投影（压扁了一个维度）。
  • |M| < 0：矩阵包含镜像（翻转）。

2. 矩阵的逆

M·M⁻¹ = M⁻¹·M = I。

  • 只有方阵可能可逆。行列式不为0的矩阵可逆（非奇异），行列式为0的不可逆（奇异）。

3. 正交矩阵

定义：M·Mᵀ = I，即逆矩阵等于转置，求逆几乎没有开销。

判定： 矩阵的每一行都是单位向量，且各行两两垂直（列同理）。

  • 旋转矩阵和镜像矩阵是正交的。
  • 事先不知道是否正交时，不要专门去检测——检测的计算量和直接求逆差不多，检测失败还白算。

九、3D中的方位与角位移

1. 方位与角位移

  • 方位：物体的朝向。向量只有方向没有方位——让向量绕自身旋转，它不会变化；物体绕自身旋转，朝向就变了。
  • 角位移：两个方位之间的旋转量。和位置一样，方位不能用绝对量描述，只能通过相对某个参考方位的旋转来描述。
  • 方位和角位移的关系类似点和向量：方位描述“朝向哪里”，角位移描述“从一个方位转到另一个方位”。数学上二者等价。
  • 常用三种表示方法：矩阵、欧拉角、四元数。

2. 矩阵形式

用3×3旋转矩阵表示，矩阵的行是物体坐标系的三个基向量在惯性坐标系中的表示（又叫方向余弦矩阵）。

  • 要明确方向：惯性→物体和物体→惯性两个矩阵互为转置。

优点：

  • 可以立即旋转向量。
  • 图形API使用矩阵，其他形式最终都要转换成矩阵。
  • 多个角位移可以直接连接（矩阵相乘）。
  • 求逆简单（正交矩阵，转置即可）。

缺点：

  • 占内存多：9个数，实际只需3个。动画数据量大时代价明显。例如15个骨骼、15Hz动画：矩阵每秒4×9×225 = 8100字节，欧拉角只要2700字节。
  • 难用、不直观：人用角度思考方位，矩阵用的是向量。
  • 可能非法：9个数中只有3个自由度，随便给9个数通常不是合法旋转矩阵；坏数据或矩阵蠕变会让它不再正交。

3. 欧拉角

定义： 把方位分解为绕三个互相垂直轴的三次旋转。本书约定：

  • heading-pitch-bank：heading绕y轴，pitch绕x轴，bank绕z轴，旋转轴是物体坐标系的轴。
  • 从惯性坐标系开始（与物体坐标系重合），依次heading、pitch、bank，就得到物体方位。
  • 正方向：heading从上往下看顺时针为正（向右转）；pitch向下为正（低头）；bank从物体前方往原点看逆时针为正。
  • 别名：飞行领域常用yaw-pitch-roll，yaw对应heading，roll对应bank。
  • 如果绕惯性坐标系的轴旋转，顺序就要反过来：bank、pitch、heading。

优点：

  • 最直观，数据就是角度，便于输入、调试。
  • 最省内存，3个数。
  • 任意三个数都是合法的欧拉角。

缺点：

  1. 别名问题：同一方位有多种表示。

    • 角度加360°的倍数方位不变。
    • 三个角不独立：pitch 135° 等价于 heading 180°、pitch 45°、bank 180°。
    • 解决：限制欧拉角——heading、bank在[-180°, 180°]，pitch在[-90°, 90°]。

  2. 万向锁：pitch = ±90° 时，heading和bank绕的是同一个轴（竖直轴），少了一个自由度。例如“heading 45°，pitch 90°”与“pitch 90°，bank 45°”等价。约定：pitch = ±90° 时 bank = 0，旋转全部放进heading。这就是限制欧拉角的完整定义。

  3. 插值困难：

    • 不限制欧拉角时，两个只差45°的方位可能插值转好几圈。
    • 即使限制了，heading从-170°到170°实际只差20°，直接插值会绕340°的长弧。可以把差值折回[-180°, 180°]：

    • 凸多边形：从一个顶点出发做扇形分解，得到n-2个三角形。
    • 凹多边形或要求更好质量：不断找到“可以切掉的耳朵”，或每次连接最短对角线，避免细长三角形。

请记住：

  • 图元有隐式、参数、直接三种表示，按需要转换。
  • 射线用p0 + t·d表示；平面用p·n = d表示，点到平面距离是q·n - d。
  • AABB用min/max表示，变换后用矩阵元素符号快速求新AABB。
  • 三角形面积用叉乘的一半；重心坐标是子三角形面积比，用于判断点在内和插值顶点属性。

十三、三角网格

1. 表示方法

三角形列表： 每个三角形直接存三个顶点坐标。简单，但共享顶点重复存储，浪费内存，也无法知道三角形之间的连接关系。

索引三角网格： 最常用。

  • 共享顶点只存一次，三角形用索引引用。
  • 可以额外存边列表等邻接信息，加速某些操作（如找相邻三角形）。

针对渲染的特殊格式：

  • 三角带：前三个顶点组成第一个三角形，之后每增加一个顶点就和前两个顶点组成新三角形。n个顶点表示n-2个三角形。注意相邻三角形的顶点顺序交替，要处理绕序。
  • 三角扇：所有三角形共享第一个顶点，适合凸多边形。
  • 需要“跳转”时可以插入退化三角形（面积为0）把多个带连起来。
  • 现代硬件有顶点缓存，索引三角形列表只要排列好顺序，效率与三角带相当。

2. 额外信息

  • 纹理映射坐标（UV）：每个顶点存一组或多组。
  • 表面法向量：
    • 三角形法向量：由边的叉乘得到。
    • 顶点法向量：用于光照计算和平滑着色。通常取相邻三角形法向量的平均（可按面积或角度加权）。
    • 平均法向量在硬边（如立方体的棱）处会让棱角变得圆滑，此时需要拆分顶点，让每个面有自己的法向量。
  • 光照值：预先计算好的顶点颜色等。

3. 拓扑和一致性

  • 拓扑：三角形之间如何连接；几何：顶点在哪里。
  • 闭合网格：每条边恰好被两个三角形共享，没有缝隙，能区分内外（实体）。
  • 常见缺陷：
    • 孤立顶点：没有被任何三角形使用。
    • 重复顶点：位置相同但索引不同，导致网格在拓扑上“断开”。
    • 退化三角形：面积为0（两个索引相同或三点共线）。
    • 开放边：只被一个三角形使用的边（网格不封闭）。
    • T型连接：一个顶点位于另一个三角形的边上而不是端点上，渲染时会出现细缝。
  • 很多算法要求网格满足一致性，导入外部模型后应先检查和修复。

4. 网格操作

  • 逐顶点/逐面操作：对所有顶点做变换，对所有三角形做翻转（改变绕序）等，最简单。
  • 焊接顶点：把位置足够接近（在容差内）的顶点合并为一个，修复重复顶点。
    • 只比较位置可能错误合并UV或法向量不同的顶点。
    • 需要高效查找邻近顶点（排序、哈希、网格划分），避免O(n²)。
    • 焊接后要更新三角形索引，删除因此产生的退化三角形。
  • 拆分顶点：焊接的反操作，在法向量、纹理坐标等不连续的地方（硬边、UV接缝）复制顶点，让每侧有独立属性。
  • 边折叠：把一条边的两个顶点合并为一个，这条边相邻的两个三角形随之退化被删除。
  • 网格消减（LOD）：反复做边折叠，每次选择对外观影响最小的边，得到不同精细程度的模型。距离远时用低精度模型。
  • 顶点缓存优化：调整三角形顺序，让顶点在缓存中尽可能被复用。

请记住：

  • 索引三角网格是最通用的表示：顶点列表 + 三角形索引列表。
  • 顶点法向量是相邻面法向量的平均，硬边处要拆分顶点。
  • 外部模型常有重复顶点、退化三角形、T型连接等问题，用焊接、清理等操作修复。
  • 边折叠是网格消减和LOD的基础。

十四、图形数学

1. 图形管道概述

渲染一帧大致经过以下步骤：

  1. 建立场景：设置摄像机、光源、雾等全局状态，清空缓冲区。
  2. 可见性检测：粗略判断哪些物体可能可见，不可见的直接跳过（见第十五章）。
  3. 设置物体级渲染状态：纹理、材质等。
  4. 几何体生成与提交：把物体的三角形和顶点数据提交给API。
  5. 变换和光照：顶点从模型空间变换到裁剪空间，并计算顶点光照。
  6. 背面剔除和裁剪：去掉背对摄像机的三角形，裁掉视锥外的部分。
  7. 投影到屏幕空间：齐次除法，映射到屏幕坐标。
  8. 光栅化：确定三角形覆盖哪些像素，插值顶点属性。
  9. 像素着色：计算每个像素的颜色，进行深度测试、alpha混合，写入帧缓冲。

步骤5~9通常由硬件完成。

2. 设置视图参数

窗口：

  • 渲染输出的矩形区域（可以是整个屏幕，也可以是一部分，如分屏）。
  • 窗口的位置和大小（像素），以及像素纵横比（物理宽高比，现代显示器通常是1:1）。

视锥：

  • 摄像机能看到的空间区域，是一个被截去顶部的四棱锥，由六个面组成：上、下、左、右，以及近裁剪面和远裁剪面。
  • 近裁剪面避免除以0和物体贴脸；远裁剪面限制绘制距离，也影响深度缓冲精度。

视场与缩放：

  • 视场（FOV）：视锥的张角。人眼视场很大，但游戏中常用60°~90°。
  • 缩放（zoom）：zoom = 1 / tan(fov/2)，比视场角更便于计算。
  • 水平和垂直的缩放必须和窗口比例一致，否则画面会拉伸：

正交投影： 没有透视效果，用于2D游戏、工程图、编辑器视图，用视图的物理尺寸代替视场。

3. 坐标空间

渲染中依次经过：

  1. 模型空间：模型自己的坐标系（物体坐标系）。
  2. 世界空间：所有物体放在一起。
  3. 摄像机空间：以摄像机为原点，+z为视线方向，+x右，+y上。用于剔除和光照。
  4. 裁剪空间：用裁剪矩阵变换后的4D齐次空间，视锥变成规则形状，方便裁剪。
  5. 屏幕空间：齐次除法后映射到像素坐标。

裁剪矩阵（透视投影）：把视锥映射为-w ≤ x, y, z ≤ w的区域（n、f为近远裁剪面距离）：

  • 第三列为1，使w = z，为透视除法做准备。
  • 裁剪空间中，点在视锥内当且仅当：-w ≤ x ≤ w、-w ≤ y ≤ w、-w ≤ z ≤ w。
  • 正交投影的裁剪矩阵不改变w（w始终为1）。

屏幕空间：

z和w也保留下来，用于深度缓冲和透视校正插值。

4. 多边形网格

  • 渲染单元通常是三角形。
  • 一个物体由多个三角网格组成，每块网格对应一种材质（纹理、光照参数）。
  • 绕序决定正面，用于背面剔除。

5. 纹理映射

  • 纹理：贴到表面上的位图，每个像素叫纹素（texel）。
  • 纹理坐标（UV）：每个顶点指定它对应纹理上的位置，通常归一化到[0,1]，与纹理分辨率无关。
  • 光栅化时在三角形内插值UV，取出对应纹素颜色。
  • UV超出[0,1]时：
    • 重复（wrap）：纹理平铺。
    • 截断（clamp）：使用边缘的纹素。
  • 透视投影下UV必须做透视校正插值（插值u/w、v/w、1/w），否则纹理会扭曲。

6. 光照和雾化

颜色运算： 颜色用RGB三元组表示，范围[0,1]。两个颜色相乘是分量分别相乘（⊗），表示光被表面过滤。

  • 聚光灯：有位置和方向，光照集中在一个圆锥内。

着色模式（在哪里计算光照）：

  • 平面着色（flat）：每个三角形算一次光照，整个三角形同色，有明显的棱面感。
  • Gouraud着色：在每个顶点计算光照，三角形内插值颜色。速度快，但高光容易丢失或形状不对（高光可能落在三角形中间）。
  • Phong着色：插值法向量，逐像素计算光照，效果最好，开销最大。

7. 缓冲区

  • 帧缓冲：保存要显示的像素颜色。
  • 双缓冲：在后台缓冲渲染，完成后与前台缓冲交换，避免画面撕裂和闪烁。
  • 深度缓冲（z-buffer）：保存每个像素当前最近表面的深度。新像素比已有深度更近才写入，从而正确处理遮挡，不必按远近排序三角形。
  • 模板缓冲：按像素做标记，用于阴影、镜面、轮廓等特殊效果。

8. 背面剔除与裁剪

背面剔除： 闭合物体背对摄像机的三角形一定被正面三角形挡住，可以直接丢弃，大约省一半工作量。

  • 判断方法：
    • 屏幕空间：投影后顶点为逆时针（本书约定正面为顺时针）就是背面。
    • 摄像机/物体空间：(p - 摄像机位置) · n > 0（从摄像机看向三角形的方向与法向量同向）就是背面，可以在变换前就剔除，更省时间。

裁剪： 三角形部分在视锥外时，必须裁掉外部部分，否则会出现除零和错误的投影。

  • 常用Sutherland-Hodgman多边形裁剪：每次用一个裁剪平面裁剪多边形。依次检查每条边：
    • 两端都在内：保留终点。
    • 从内到外：保留交点。
    • 从外到内：保留交点和终点。
    • 两端都在外：什么也不保留。
  • 一个三角形被多个平面裁剪后可能变成多边形，再三角化渲染。
  • 在裁剪空间裁剪最简单，因为六个平面都是±w的形式。

9. 光栅化

  • 扫描转换：确定三角形覆盖了哪些像素（常用的是逐扫描线填充）。

  • 对覆盖的每个像素：

    1. 插值深度、颜色、UV等属性。
    2. 深度测试：比深度缓冲中的值更远就丢弃。
    3. 计算颜色（纹理采样、光照、雾化）。
    4. alpha混合：半透明物体与已有颜色混合：
    1. 写入帧缓冲和深度缓冲。

  • 半透明物体需要在不透明物体之后，从远到近渲染。

请记住：

  • 图形管道：场景 → 可见性 → 状态 → 提交 → 变换与光照 → 剔除与裁剪 → 投影 → 光栅化 → 着色。
  • 坐标空间：模型 → 世界 → 摄像机 → 裁剪 → 屏幕；裁剪矩阵把视锥变成-w ≤ x,y,z ≤ w。
  • 标准光照 = 镜面（Phong/Blinn）+ 漫反射（Lambert）+ 环境光；着色方式有平面、Gouraud、Phong。
  • 深度缓冲解决遮挡；背面剔除省掉一半三角形；裁剪处理跨越视锥的三角形。

十五、可见性检测

可见性检测在渲染之前粗略地排除不可见的物体，减少提交给硬件的数据。目标不是精确，而是保守：可能可见的必须保留，明显不可见的尽量剔除。

1. 包围体检测

用包围体代替复杂物体： 先检测物体的包围球或AABB，包围体不可见，物体一定不可见。

视锥剔除：

  • 包围球：分别求球心到视锥六个平面的距离，若对任一平面完全在外侧（距离 < -r）就剔除。
  • 裁剪空间区域码：把包围体的8个角点变换到裁剪空间，每个点按六个条件生成6位编码：
  • 按位与为0不代表一定可见（包围体可能跨过视锥的角落），但作为保守剔除足够了。

遮挡剔除： 物体在视锥内，也可能被其他物体挡住。遮挡检测更复杂，通常依赖空间结构（如入口技术）或预计算（PVS）。

2. 空间分割

逐个检测每个物体的包围体，开销仍随物体数线性增长。空间分割把世界划分成区域，一次排除整个区域，并加速射线检测、碰撞查询（“这附近有什么”）。

3. 网格系统

  • 把世界划分成规则的2D或3D网格，每个格子保存其中的物体列表；跨多个格子的物体在每个格子中都登记（或只登记在一个格子中并扩大查询范围）。
  • 查询时只需检测视锥或射线经过的格子。
  • 优点：简单、查询定位快（直接计算格子索引）。
  • 缺点：格子大小难选；物体分布不均时，很多格子空着浪费内存，密集处效率差。

4. 四叉树和八叉树

  • 四叉树（2D）：每个节点是一个正方形区域，细分为4个相等的子区域；八叉树（3D）：每个节点细分为8个子立方体。
  • 只在需要的地方细分（物体多就继续分，物体少就停），自适应地处理分布不均的世界。
  • 物体放在能完全包含它的最小节点中。问题：跨越分割线的小物体会停留在很高层的节点。解决：松散四叉树/八叉树——每个节点的包围盒适当放大，允许物体稍微超出。
  • 视锥剔除：从根节点递归，节点包围盒完全不可见就跳过整棵子树；完全可见则整棵子树都可见，不再检测。
  • 射线检测：只进入射线穿过的节点，按射线经过的顺序访问，找到最近交点后可提前结束。

5. BSP树

  • BSP（二叉空间分割）树：每个节点用一个任意平面把空间分成正面和背面两半，递归直到满足终止条件。
  • 比八叉树更灵活：分割平面可以贴合场景几何（如墙面）。
  • 经典用法：用场景中的多边形作为分割平面，可以在任意视点下得到严格的从后到前绘制顺序（画家算法），不需要深度缓冲；也用于碰撞检测。
  • 跨越分割平面的多边形要被切分成两部分。
  • 构造关键是选择分割平面：要平衡（树的深度小）又要减少切分（多边形数量少），两者通常需要折中，常用启发式评分。
  • BSP树构造慢，一般预计算，适合静态场景。

6. 入口技术

  • 适用于室内场景：把世界分成房间（cell），房间之间通过入口（portal）（门、窗、走廊口等多边形）连接。
  • 渲染时：
    1. 渲染摄像机所在的房间。
    2. 对房间中的每个入口，若它在当前视锥内可见，就用入口的边界缩小视锥。
    3. 用缩小后的视锥递归渲染入口另一侧的房间。
  • 被墙挡住的房间根本不会被访问，天然实现了遮挡剔除。
  • 也可以用屏幕空间的矩形近似入口，简化计算。
  • 还可以实现镜子、传送门等效果（让入口通向变换后的另一个空间）。

7. 潜在可见集（PVS）

  • 预先为每个区域计算一个列表：从该区域内任意位置可能看到哪些区域（或物体）。
  • 运行时只渲染PVS中的内容，再配合视锥剔除。
  • 预计算很耗时，结果需要存储空间，只适用于静态场景。
  • 常与BSP树或入口技术结合使用。

请记住：

  • 可见性检测追求保守和快速：宁可多画，不能漏画。
  • 包围体 + 视锥剔除是基础；裁剪空间区域码按位与非零即可剔除。
  • 网格、四叉树/八叉树、BSP树通过空间分割一次排除大片区域；BSP能给出严格的前后顺序。
  • 室内场景用入口技术逐房间缩小视锥；静态场景可预计算PVS。
